# 명확한 기술 문서

- 첫 문장에 문제나 결과를 쓴다. 작업한 순서보다 독자가 판단하는 순서로 설명한다.
- 주체와 동작을 명확히 한다. ‘처리가 수행될 수 있도록 개선’보다 ‘서버가 실패한 요청을 다시 처리한다’처럼 쓴다.
- 추상적인 평가를 관찰할 수 있는 사실로 바꾼다. ‘품질 개선’보다 바뀐 동작과 검증을 설명한다.
- 확인된 사실, 추정, 제안을 구분한다. 불확실성을 숨기기 위해 단정하거나 근거 없는 수치를 추가하지 않는다.
- API, 식별자, 파일명, 명령은 정확히 보존한다. 한국어로 옮기면 의미가 달라지는 용어는 원어를 유지하고 필요한 경우 짧게 설명한다.
- 표는 비교와 대응 관계에, 목록은 병렬 항목에 사용한다. 단순한 문장까지 제목과 체크리스트로 쪼개지 않는다.
- 중복과 상투어를 줄이되 제약, 예외, 결정 근거, 검증 한계를 삭제하지 않는다.
- 사용자가 정한 말투, 양식, 문서 길이를 따른다. 문서 교정 요청을 제품 방향 변경으로 확대하지 않는다.

완료 전에 원문의 의미, 링크, 수치와 코드 표현이 유지됐는지 확인한다. 편집할 문서가 없으면 대상 내용을 확인한다.
