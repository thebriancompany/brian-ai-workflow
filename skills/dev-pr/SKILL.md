# PR 작성과 제출

사용자가 요청한 제출 범위를 따른다. 실제 PR 생성 요청은 필요한 커밋·푸시·생성을 포함하므로 단계별 재승인을 요구하지 않는다. 커밋만, 로컬 검토만, 초안만 요청한 경우 그 경계를 지킨다. 병합·배포·리뷰어에게 메시지 전송을 추가하지 않는다.

## 1. 상태와 대상 확인

- `AGENTS.md`, 현재 브랜치, staged·unstaged·untracked, 기존 커밋을 확인한다. 사용자 변경이 섞여 있으면 작업과 관련된 파일 또는 변경 부분만 선택한다. 처음부터 stage된 무관한 변경도 커밋에서 제외하고 원래 staging 상태를 보존한다. 같은 변경 부분에 섞여 분리할 수 없으면 확인한다. 무차별 전체 staging을 하지 않는다.
- 원격 주소와 사용자가 지정한 대상을 확인한다. 기존 PR의 대상, 저장소 설정, 원격 기본 브랜치로 기준 브랜치를 결정한다. 모호하면 묻고 `origin`이나 `main`을 고정 가정하지 않는다.
- 기본 브랜치나 detached HEAD에서 바로 게시하지 않는다. 변경을 보존한 작업 브랜치를 준비하거나 필요한 대상을 확인한다.
- 기존 PR이 있는지 조회한다. 있으면 중복 생성 대신 요청에 맞게 갱신한다. 변경도 새 커밋도 없으면 제출할 내용이 없다고 알린다.

## 2. 검증과 커밋

프로젝트에서 정의한 포맷·정적 분석·테스트·필요한 빌드를 실행한다. 같은 코드 상태에 대해 이미 확인한 결과는 재사용할 수 있다. 수정 이후 결과가 낡았거나 일부가 누락되었으면 해당 검사를 실행한다. 검사 생략 문자열 하나로 모든 검증을 우회하지 않는다.

필수 검사 실패 또는 필수 수동 확인 대기가 있으면 해결하거나 미완료를 표시한다. 환경 때문에 실행할 수 없는 검증을 통과로 적지 않는다. 명시적으로 초안 PR을 요청한 경우에는 미완료 내용을 제목·본문과 상태에 드러내고 초안으로 생성할 수 있다.

요청된 파일만 stage하고 staged diff를 다시 읽는다. 비밀값, 임시 로그, 관련 없는 변경이 포함되지 않았는지 확인한다. 커밋은 프로젝트 관례를 따른다. 관례가 없으면 `feat: ...`, `fix: ...`, `docs: ...` 등 목적이 드러나는 제목을 사용한다. 이미 적절한 커밋이 있으면 불필요하게 합치거나 다시 쓰지 않는다.

## 3. 본문과 게시

저장소의 PR/MR 양식을 우선한다. 없으면 [본문 양식](references/pr-template.md)을 사용한다. 이전 대화의 경과보다 문제, 최종 동작, 실제 검증을 설명한다.

1. 대상 원격과 브랜치에 일반 push한다. 거절되면 원인을 확인하고 강제 push로 우회하지 않는다.
2. 설치된 Git 호스팅 도구로 PR/MR을 생성한다. 특정 CLI나 커넥터가 필수라고 가정하지 않는다. 둘 다 없으면 본문과 차단 이유를 남긴다.
3. CLI에 여러 줄 본문을 전달할 때 임시 UTF-8 파일과 `--body-file` 등 해당 도구의 파일 입력을 사용한다. 본문을 셸 코드로 직접 조합하지 않는다.
4. PR 이벤트로 시작하는 CI는 PR 생성 후 확인한다. 아직 실행 중이면 대기 중이라고 표시한다. 같은 실행을 계속 촘촘하게 조회하거나 영구 모니터를 임의 생성하지 않는다.
5. 현재 환경에 PR 첨부 도구가 있으면 생성한 PR을 채팅에 첨부한다. URL, 대상 브랜치, 검증과 CI 상태를 전달한다.

게시가 실패하면 실제로 완료된 커밋·푸시·PR 상태를 구분해 보고한다. 이미 생성된 PR을 확인하지 않고 같은 요청을 반복하지 않는다.
