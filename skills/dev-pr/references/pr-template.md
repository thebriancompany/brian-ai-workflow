# PR 본문 양식

작은 변경은 문제와 결과를 한 문단으로 쓰고 검증을 덧붙이면 충분하다. 저장소 양식이 있으면 그 양식이 우선한다.

```markdown
## 변경 이유와 결과
어떤 상황에서 어떤 문제가 있었으며 이제 어떻게 동작하는지 설명한다.

## 주요 변경
- 검토자가 알아야 하는 구현·계약 변화.

## 검증
- 실제 실행한 명령과 결과.
- 수동 확인한 동작 또는 아직 확인하지 못한 내용.

## 주의할 점
호환성, 마이그레이션, 알려진 제한, 복구 절차 중 해당 항목만 작성한다.

## 관련 자료
관련 이슈, 계획, 필요한 리뷰 결과.
```

빈 항목은 삭제한다. 검토에 필요하지 않은 작업 기록과 자화자찬을 넣지 않는다. 이슈를 자동 종료하는 표현은 실제로 해결한 이슈에만 사용한다.
