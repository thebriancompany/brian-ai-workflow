# 계획 기술 검토

대상 문서와 실제 저장소를 읽고 계획대로 구현했을 때의 문제를 찾는다. 리뷰만 요청받았으면 원문과 코드를 수정하지 않는다.

## 검토 관점

- **정확성:** 경로, 공개 API, 의존성 버전, 명령과 실행 폴더가 실제 환경에 맞는가?
- **완전성:** 요구사항이 작업과 완료 기준에 연결되는가? 중요한 실패, 권한, 동시성, 데이터 변환 경로가 빠지지 않았는가?
- **구조:** 기존 경계와 계약을 따르는가? 불필요한 의존성이나 추상화를 추가하지 않는가?
- **검증:** 명령이 의도한 동작을 증명하는가? 수동 확인은 기대 결과가 분명한가? 테스트·실행 환경을 실제로 준비할 수 있는가?
- **범위:** 독립적으로 적용하고 검증할 수 있는 단위인가? 분할이 필요하면 각 부분이 동작하도록 경계와 선행 관계를 제안한다.
- **전환:** 호환성, 마이그레이션, 순차 배포, 복구가 필요한 변경에 대응책이 있는가?

사용자 의미가 달라지는 결정과 구현상 고칠 수 있는 결함을 구분한다. 외부 API의 현재 지원 여부가 불확실하면 공식 문서를 확인한다.

## 결과

`준비됨`, `수정 후 준비됨`, `결정 또는 환경 확인 필요` 중 근거에 맞는 판단을 내린다. 발견 사항마다 계획의 위치, 코드 근거, 예상 영향, 수정 제안을 적는다. 확인하지 못한 내용도 명시한다.

사용자가 보완까지 요청했다면 기존 문서에 반영하고 변경 요약을 남긴다. 자동으로 이슈, PR, 제품 코드 변경을 만들지 않는다. 이미 검토된 계획도 관련 코드나 요구가 바뀌었을 때만 영향을 받는 부분을 다시 검토한다.
