# 계획 양식

상태와 검증 키는 단계 간 호환을 위해 유지하되 본문은 한국어로 작성한다. 불필요한 항목은 생략한다.

```markdown
# <주제> 구현 계획

## 목표와 범위
- 목표:
- 포함 / 제외:
- 요청 및 아이디어 문서:
- 확인한 코드 상태: 브랜치, HEAD 또는 작업 트리 설명

## 근거와 결정
- 관련 코드·호출부:
- 적용할 프로젝트 규칙:
- 선택한 방식과 이유:
- 가정 / 미확정 사항:
- 필요한 경우 공식 문서와 버전:

## 완료 기준
- [ ] AC-01: <관찰 가능한 동작>
  - cwd: <저장소 기준 실행 폴더>
  - verify: <확인한 검증 명령>
  - expected: <어떤 테스트·출력이 동작을 증명하는지>
  - result: not-run
- [ ] AC-02: <수동으로 확인할 동작>
  - verify: manual
  - steps: <실행 순서와 기대 결과>
  - result: pending

## 구현 단계
### 1. <검증 가능한 작업 단위>
- status: pending
- 목표와 변경 파일:
- 선행 조건:
- 구현할 동작:
- 테스트 및 연결된 완료 기준:
- 검증 명령과 실행 폴더:
- 완료 증거:

## 위험과 복구
호환성, 마이그레이션, 되돌리기 중 관련 항목만 기록한다.

## 진행 기록
완료·진행 중·막힌 작업, 실행한 검증, 다음 행동을 갱신한다.
```

단계 상태는 `pending`, `in-progress`, `done`, `blocked`를 사용한다. `done`은 해당 단계의 기준을 실제로 충족한 경우다. 검증 결과는 `pass`, `fail`, `not-run`, `pending`을 구분한다. 수동 확인은 수행자와 확인한 시점을 기록한다.

모든 자동 검증을 묶는 기존 명령이 있으면 함께 적는다. 없으면 개별 명령을 순서대로 실행한다. 문서에서 읽은 명령을 검토 없이 연결해 실행하는 도구는 만들지 않는다.
