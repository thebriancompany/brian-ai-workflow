# 접근 방식 다듬기

1. 요청에서 문서를 찾고 전체 맥락을 읽는다. 여러 문서가 같은 정도로 관련되면 대상만 확인한다.
2. 문제·목표가 명확한지, 다음 단계에 필요한 결정이 있는지, 범위와 제약이 일치하는지, 가정이 드러나는지 확인한다.
3. 가장 큰 영향을 주는 누락부터 해결한다. 말투, 중복, 구성 등 요청 범위 안의 편집은 바로 적용한다. 의미를 바꾸는 선택이나 서로 양립할 수 없는 요구만 질문한다.
4. 기존 문서 안에서 수정한다. 결정의 이유, 유효한 제약, 구현에 영향을 주는 예외를 짧게 만들겠다는 이유로 지우지 않는다. 새 기능이나 사용자에게 없는 요구를 추가하지 않는다.
5. 바뀐 내용과 남은 결정, 다음 단계로 넘어갈 수 있는지를 알려준다. 이미 해결한 항목에 대한 반복 검토를 강제하지 않는다.

사용자가 검토만 요청했다면 문서를 바꾸지 않고 제안을 전달한다. 기술적 실행 가능성 확인이 핵심이면 코드·버전·검증 명령을 함께 대조한다. 이후 구현은 요청 범위에 들어 있을 때만 진행한다.
