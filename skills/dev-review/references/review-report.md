# 리뷰 결과 형식

## 우선순위와 식별

- `P0`: 즉시 대응해야 하는 심각한 장애·데이터 손상 등 확실한 차단 문제.
- `P1`: 배포·병합 전에 해결할 가능성이 높은 중대한 동작 오류.
- `P2`: 특정 조건에서 발생하는 일반 결함이나 중요한 검증 누락.
- `P3`: 낮은 영향의 개선 제안. 실제 이유가 있을 때만 포함.

같은 위치에서 같은 원인으로 생기는 문제는 합친다. 우선순위 → 파일 경로 → 줄 번호 → 규칙 순으로 정렬한 뒤 `FINDING-01`부터 부여한다. 규칙은 `correctness/duplicate-submit`, `tests/missing-error-case`처럼 관점과 문제 유형을 조합한다.

ID는 **해당 보고서 안에서만** 유효하다. 발견 사항이 달라진 다른 실행에서는 번호가 바뀔 수 있다. 과거 항목은 보고서 경로와 ID로 식별한다. 채팅과 문서는 같은 목록에서 요약하여 번호와 제목이 어긋나지 않게 한다.

```markdown
# 코드 리뷰

- 범위 / 기준 브랜치 / 기준 커밋 / 대상 코드 상태:
- 수행한 관점:
- 실행한 검증과 결과:
- 미실행 또는 불완전한 검토:

| ID | 우선순위 | 규칙 | 위치 | 제목 |
| --- | --- | --- | --- | --- |

## FINDING-01: <제목>
- 위치: <실제로 확인한 파일과 줄>
- 조건과 근거:
- 영향:
- 수정 방향:
- 상태: open / fixed / deferred

## 남은 확인 사항
실행하지 못한 검사, 불확실한 가정, 범위 밖 관찰.
```

계획·코드 변경으로 위치가 달라지면 수정 당시 위치를 함께 남긴다. 수정이 끝났어도 보고서를 자동 삭제하지 않는다.
