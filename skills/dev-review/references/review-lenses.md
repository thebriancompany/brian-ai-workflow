# 리뷰 관점

## 동작과 계약

입력 검증, 경계값, 오류 전파, 반환값, 상태 전이와 기존 호출자 호환성을 실제 코드로 추적한다. 비동기·동시 처리가 있으면 취소, 중복 요청, 순서 역전, 자원 해제를 살핀다. 보안·성능은 이번 변경과 관련 있고 근거가 있는 문제를 다룬다.

## 아키텍처와 관례

프로젝트가 선택한 경계와 의존 방향을 확인한다. 계층형, 포트·어댑터, 기능 중심 구조 등 서로 다른 설계를 하나의 표준으로 평가하지 않는다. 순환 의존, 구현 누출, 자원 수명 문제를 찾아 영향과 근거를 제시한다. 테스트 대역이나 경계를 위한 인터페이스는 구현이 하나라는 이유만으로 제거 대상으로 삼지 않는다.

## 테스트 품질

테스트가 관찰 가능한 요구를 증명하는지 본다. 성공뿐 아니라 중요한 실패와 경계 조건, 버그의 수정 전 실패 여부를 확인한다. 테스트 대상 자체를 대역으로 바꾸거나 구현을 복사한 기대값, 불필요한 내부 호출 검증, 비동기 완료 대기 누락을 찾는다. 커버리지 숫자나 파일별 테스트 개수만으로 품질을 판단하지 않는다.

## 단순성과 범위

현재 요구와 연결되지 않는 기능, 과도한 설정, 중복된 정책, 이해를 방해하는 간접 계층을 찾는다. 단순화로 잃는 호환성·오류 처리·확장 계약도 확인한다. 기존 문서나 사용자 변경을 정리 명목으로 지우지 않는다.

## 제출 준비

요청된 경우 변경에 필요한 포맷·정적 분석·테스트·빌드 결과, 생성 파일·잠금 파일 일치, 디버그 코드, 민감 정보 포함 여부, PR 범위와 제목을 확인한다. 실행한 검사와 코드만 읽은 검사를 분리한다. 설치되지 않은 도구나 실패한 관점은 누락으로 기록한다.
