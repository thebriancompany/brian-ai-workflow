# 개발 워크플로우

Codex에서 사용하는 한국어 개발 스킬 모음입니다. 아이디어 정리부터 계획, 구현, 검증, 리뷰, PR과 회고까지 연결합니다. 웹, 서버, 모바일, 데스크톱, 라이브러리, CLI 등 프로젝트의 실제 기술과 관례를 따릅니다.

## 바로 시작하기

`skills/` 아래의 13개 폴더를 `~/.agents/skills/`에 복사하면 됩니다. 각 폴더 안의 `SKILL.md`, `agents/`, `references/`, `LICENSE`를 함께 유지하세요. 별도 실행 프로그램이나 설치 스크립트는 필요하지 않습니다.

Codex에서 스킬이 보이지 않으면 새 채팅에서 확인하거나 앱을 다시 시작하세요.

작업할 프로젝트를 Codex에서 열고 다음처럼 요청합니다.

```text
$dev-workflow 검색 결과 필터 기능을 계획부터 구현과 검증까지 진행해줘.
```

스킬 이름과 설명으로 자동 선택할 수도 있습니다. 정확한 흐름을 지정하려면 `$dev-workflow`처럼 호출하세요. 이 이름들은 Codex의 내장 슬래시 명령이 아닙니다.

## 기본 흐름

```text
아이디어 정리 → 구현 계획 → 구현·검증 → 코드 리뷰 → 요청 시 PR
    ↑              ↑           ↑
    └── 접근 개선 ──┘           └── 발견 사항 수정과 재검증

긴급 버그: 재현 → 최소 수정 → 회귀 검증 → 리뷰
장애 이후: 증거 수집 → 원인 분석 → 예방·탐지·대응 조치
```

작은 수정은 바로 구현부터 시작합니다. 이미 명확한 요구사항에 아이디어 탐색을 강제하지 않습니다. 전체 구현을 요청하면 승인된 범위 안에서 계속 진행하고, 계획이나 리뷰만 요청하면 해당 단계에서 끝납니다.

## 자주 쓰는 요청

**아이디어부터 정리할 때**

```text
$dev-brainstorm 팀 초대 기능을 만들려고 해. 기존 사용자 권한 구조를 보고 접근 방법을 비교해줘.
```

**계획만 검토하고 싶을 때**

```text
$dev-plan 파일 업로드에 재시도를 추가하는 계획을 작성해줘. 아직 구현하지 마.
```

**기존 계획을 구현하거나 이어서 진행할 때**

```text
$dev-build docs/workflow/upload-retry/plan.md를 읽고 미완료 단계부터 구현해줘.
```

**빠르게 버그를 고칠 때**

```text
$dev-hotfix 저장 버튼을 두 번 누르면 요청이 중복돼. 재현하고 최소 변경으로 수정해줘.
```

**리뷰만 받을 때**

```text
$dev-review 현재 브랜치 변경을 리뷰해줘. 코드는 수정하지 마.
```

**검증한 변경을 제출할 때**

```text
$dev-pr 이번 작업의 변경만 커밋하고 푸시해서 PR을 만들어줘.
```

## 프로젝트에 맞춰 동작하는 방식

- 적용되는 `AGENTS.md`, 기존 코드, 의존성·잠금 파일, 실행 스크립트와 CI에서 규칙과 검증 명령을 찾습니다.
- 특정 언어, 계층 구조, 상태 관리 도구, 테스트 명령을 고정하지 않습니다.
- 테스트는 동작과 위험을 검증합니다. 파일마다 형식적인 테스트를 만드는 방식은 요구하지 않습니다.
- 버전별 API나 외부 서비스 동작이 불확실하면 공식 자료로 확인합니다.
- 전문 스킬이 설치되어 있으면 필요한 것만 사용합니다. 별도 플러그인이나 병렬 에이전트 없이도 진행할 수 있습니다.
- 구현 요청만으로 커밋·푸시·PR·배포를 추가하지 않습니다. 이미 요청한 동작은 반복 승인 없이 진행합니다.

## 산출물과 작업 재개

프로젝트의 문서 경로가 있으면 그 관례를 따릅니다. 없으면 다음 경로에 필요한 문서만 만듭니다.

```text
docs/workflow/<주제>/
  brainstorm.md         결정과 대안
  plan.md               작업, 완료 기준, 검증 결과, 진행 상태
  reviews/<실행ID>.md    보존되는 리뷰 결과
  handoff.md            긴 작업의 재개 맥락
  debrief.md            필요한 경우 장애 회고
```

계획의 `done`은 검증한 단계 완료를 뜻하며 커밋·배포 완료와는 다릅니다. `pass`, `fail`, `not-run`, `pending`으로 검증 결과를 구분합니다. 새 채팅에서는 문서 경로와 목표를 알려주면 현재 코드와 대조하여 이어갑니다. 단계마다 채팅을 초기화할 필요는 없습니다.

리뷰의 `FINDING-01` 같은 번호는 한 보고서 안에서 유효합니다. 다른 실행의 항목을 지정할 때는 보고서 경로도 함께 적으세요.

## 설치 범위와 제거

아래 중 한 곳에 스킬 폴더를 복사하세요. 같은 스킬을 여러 검색 경로에 설치하면 중복으로 보일 수 있습니다.

| 사용 범위 | 복사할 위치 |
| --- | --- |
| 모든 프로젝트 | `~/.agents/skills/` |
| 특정 프로젝트 | `<프로젝트>/.agents/skills/` |

같은 이름의 스킬이 있으면 내용을 확인한 뒤 갱신하세요. 제거할 때는 이 묶음에서 복사한 스킬 폴더만 삭제하면 됩니다.

복사 대신 심볼릭 링크로 연결한 경우에도 별도 스크립트 없이 사용할 수 있습니다. 이 경우 원본 저장소의 위치를 유지하고, 제거할 때는 설치 경로의 연결만 삭제하세요.

## 구성

```text
plugin.json       배포용 플러그인 메타데이터
skills/           한국어 스킬, UI 메타데이터, 필요한 참고 양식
docs/             설계와 사용 시나리오
LICENSE           라이선스 원문
THIRD_PARTY_NOTICES.md  제3자 라이선스 안내
```

[설계 원칙](docs/design.md)과 [시나리오 점검](docs/scenarios.md)에서 변경 이유와 기대 동작을 확인할 수 있습니다. `plugin.json`은 배포를 준비한 메타데이터이며, 공개 디렉터리에 게시되었다는 의미는 아닙니다.

Codex의 검색 경로, `$스킬명` 호출, 심볼릭 링크 지원은 [공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills)에 맞췄습니다. 배포 구조는 [공식 플러그인 문서](https://developers.openai.com/plugins/build/plugins)를 따릅니다. 기능 제공 방식은 설치된 Codex 버전에 따라 달라질 수 있습니다.
